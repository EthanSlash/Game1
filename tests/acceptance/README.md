# tests/acceptance — 黑箱驗收

這裡的測試由 **MiniMax31** 維護：只照 `docs/GDD.md` 的公式與規則寫，**不看 src/core 的實作**。

## 規則

- 只 import `src/core` 的**公開進入點**（`src/core/index.ts`）與 `data/balance.json`，不 import 內部檔案。
- 測試檔名 `*.test.ts`，由 `npm test`（vitest）一起跑；與單元測試共用同一個 runner。
- 期望值必須寫成「GDD 公式算出來的數字」，不要在測試裡重算實作邏輯。
- 不為了讓測試通過而改期望值；先確認是 GDD 寫錯還是實作錯，再回報給該工單負責人。

## 必測邊界（來自計畫 v0.1）

| 項目 | 案例 |
|---|---|
| 購買 | 錢不夠要拒絕且狀態完全不變；錢剛好等於價格要成功 |
| 離線收益 | 0 秒 / 剛好到上限 / 超過上限（截斷）/ 時鐘倒退（不給） |
| 存檔 | 損毀資料、舊版本存檔遷移 |
| 里程碑 | 25 / 50 / 100 級前後的速度倍率 |
| 背景回來 | 不能重複計算同一段時間的收益 |
| 數字格式 | 9999 / 1萬 / 1億 / 1兆 |

目前目錄是空的（M1 尚未交付引擎）。M1 完成前先在此目錄建檔，用 `it.skip` 標註等待中的案例。
